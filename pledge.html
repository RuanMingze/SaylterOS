项目愿景

SaylterOS 是一个野心勃勃的自学项目 —— 我们要写一个真正能在现代 PC 上引导启动的操作系统。 不是跑在浏览器里的模拟环境，不是给 qemu 喂个内核镜像就完事的玩具，而是从 512 字节的引导扇区 开始， 一行汇编一行 C，构建出一个有自己的内核、中断处理、内存管理、进程调度、文件系统和 Shell 的完整 OS。


启动方式：BIOS Legacy MBR 引导（第一阶段），后续扩展到 UEFI。 测试环境：QEMU (x86_64-softmmu)，最终能跑在真实 PC 硬件上。 架构路线：引导阶段先进入 32 位保护模式完成内核搬运与页表建立，随即切入 x86-64 长模式，所有子系统都运行在 64 位内核中。


目标很明确 —— 当这个项目完成的那天，我应该能不查任何资料，凭记忆讲清楚： 从按下电源键到 Shell 显示提示符的每一条 CPU 指令。

我的承诺

📚
汇编优先
bootloader、IDT 存根、上下文切换 —— 该用汇编的地方绝不偷懒。GDT 每条描述符的 8 个字节都是我亲手算出来的。
🧩
分层架构
Bootloader → Kernel → Driver → VFS → Process → Shell。每层只通过清晰的接口和下一层对话。改一个驱动不影响内核主体。
🔬
先在 QEMU 跑通，再上真机
每一个阶段都要能在 QEMU 里稳定运行，能通过 GDB 单步调试，确认无误后再烧到 U 盘上真实硬件测试。
🧠
手写内核，不抄教程
参考《Writing an OS in Rust》《OSDev Wiki》《xv6》，但每一行代码都是自己写的。看懂原理再动手，而不是复制粘贴。
♻️
能跑 > 能看
先让打印 "Hello" 的 bootloader 能跑，再加 GDT，再加中断。一步一加，每一步都能引导启动、能调试、能截图。
🎯
交付即学习
如果最终只写出了一个能打印 VGA 文本的 bootloader，那也不算失败 —— 因为我会比 99% 的程序员更懂 x86 启动流程。

诚实的边界声明

✅ 我们能做到的：

一个真正能在 x86 PC 上引导启动的裸金属 OS。产物是可写入 U 盘的 .img 或可刻录的 .iso。 它有自己的 bootloader、GDT/IDT、中断处理、物理/虚拟内存管理、进程调度、文件系统、Shell。 启动后能看到我们自己画的界面，能响应键盘输入，能执行我们自己写的命令。


⚠️ 技术现实：

x86 裸金属 OS 开发是一个极其陡峭的学习曲线。没有 libc、没有操作系统 API、没有堆、 甚至 main 函数都不会被自动调用。每一步都可能卡住好几天。这很正常 —— 这就是学习本身。


🎯 真正的目标：

理解操作系统从按下电源键到 Shell 提示符出现的每一个字节、每一条指令、每一次中断。 到这个项目结束的那天，我应该能不查资料，凭记忆画出完整的启动链路和内存布局。
