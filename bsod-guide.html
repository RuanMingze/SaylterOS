蓝屏之后怎么恢复

SaylterOS 的蓝屏不是装饰。进入蓝屏后系统会关闭中断、屏蔽 8259 全部 IRQ、停止所有任务， 并且不再执行任何磁盘写入。CPU 冻结在 cli; hlt 循环里，只能靠电源键或复位离开。 这份文档说明恢复步骤、错误码含义，以及未来会出现的蓝屏类型该怎么处理。

恢复步骤

  1. 先记录 STOP 码和 Reason
    屏幕第 7、9 行分别是 *** STOP: 0x........ 和 Reason: ...，拍照或抄下来。
  2. 查看串口日志
    始终会输出一行 [BSOD] stop=0x........ reason=...，比屏幕更容易复制。
  3. 重启机器
    实机按电源键或复位；QEMU 关闭窗口即可，也可以在 monitor 里执行 system_reset。
  4. 对照错误码处理
    按下表定位原因；如果是配置类问题，只在下次启动前处理。
  5. 反复蓝屏时回看最近改动
    优先检查新加的模块是否让 .data 越过加载上界、是否引入了 SSE 指令、是否在中断里切栈。

错误码对照表

STOP 码 名称 含义与触发场景 怎么处理
0x00000000 KERNEL_KILLED 已实现 执行 kill 0 并二次确认后主动触发。内核任务不可被正常终止，因此走崩溃处理。 重启即可，不涉及数据损坏。它同时是蓝屏流程的自检入口。
0x00000001 HEAP_EXHAUSTED 规划 内核堆（1MB）在回收之后仍无法满足分配请求。 减少同时运行的脚本、降低 alloc 大小；重启可清空堆。
0x00000002 TASK_QUOTA_EXCEEDED 规划 脚本申请内存超过任务配额。当前实现只杀任务并打印 [OOM]，不进蓝屏。 看到 [OOM] task ... killed 说明任务已被回收，无需重启；修改脚本或调大配额。
0x00000003 KERNEL_STACK_OVERFLOW 规划 内核栈越过守护页（需要先实现栈保护）。 减少深层递归与大的栈上数组；检查最近新增模块的局部变量。
0x00000004 PAGE_FAULT 规划 分页启用后访问未映射页或权限不符（#PF）。 检查页表映射与 CR3；确认 VBE 帧缓冲、内核镜像已正确映射。
0x00000005 GENERAL_PROTECTION 规划 段选择子非法或越权访问（#GP）。 检查 GDT 描述符、段寄存器加载顺序，以及 iret 返回的 CS。
0x00000006 TRIPLE_FAULT 规划 异常处理过程中再次异常，CPU 直接复位。蓝屏可能来不及显示。 用 QEMU -d int 抓复位前现场；重点查 IDT 与 ISR 的 error code 处理。
0x00000007 ACPI_TABLE_INVALID 规划 RSDP/FADT/MADT 校验失败或字段越界，主动停机以避免写坏 PM 寄存器。 换回上一个内核；或启动参数里跳过 ACPI，只保留 8042 重启。
0x00000008 SMP_AP_BOOT_FAILED 规划 INIT-SIPI-SIPI 后 AP 未在超时内上线。 QEMU 下检查 -smp 参数；实机可先限制为单核启动。
标 规划 的条目是错误码表的设计占位：内核还没有实现对应检测。 先把编号和处置方式定下来，等分页、SMP、栈保护落地时直接接入，不必再改文档结构。

为什么蓝屏必须冻结系统

关中断 + 屏蔽 8259

崩溃后键盘、时钟、串口中断全部停止，避免在处理函数里再次触发异常，把可诊断的蓝屏变成三重故障复位。

不写磁盘

FAT 缓存可能处于脏状态。崩溃后继续回写会产生半写目录项，把一次可恢复的故障变成文件系统损坏。

hlt 冻结 CPU

不再执行任何指令，寄存器与内存保持崩溃瞬间的状态，便于配合串口日志或 GDB 复盘。

只留一条串口摘要

不逐字符刷屏，避免 9600 波特率下输出拖慢冻结过程；完整诊断由屏幕承担。

触发蓝屏自检

想确认蓝屏流程与冻结是否正常，用 root 登录后执行：

root@os:~# kill 0
kill: the kernel task cannot be terminated normally.
Trigger the crash handler and show BSOD? [y/N] y

[BSOD] stop=0x00000000 reason=kernel task terminated by user request

屏幕会立刻切成蓝底白字并冻结。此时键盘无响应是预期行为，重启即可恢复。
